# 采样覆盖优化验证（0.16.2）

验证日期：2026-11-18。分支：`codex/sampling-coverage`。本次验证抽帧覆盖和实际图片请求，未调用真实云模型，未发布线上。

## 结果

固定的 17 段原片，各走完整片段与本地导入两条路径，共 34 项检查。旧版通过 20/34（每条路径 10/17），新版通过 34/34（每条路径 17/17），没有由通过变为未通过的样本。原片用 SHA-256 固定，标注来自独立查看原始全画面；导入的时间偏移已映射回原片。

这里只能说明明确可见腾空片段内的取帧覆盖，不能称作精确定位离台、完整腾空时长或动作识别正确率。blacktest 的 9.145–9.248333 秒是板仍完整可见的保守核心，后续板出画，不用它推断落地。

## 修改

1. 保留可靠人物轨迹的升降估计，优先级不变。
2. 仅检测到人物可见时段时，保留更宽的前后余量；相对原始首末可靠检测约为前 0.8 秒、后 2 秒。人物识别丢失不再当作动作结束。
3. 无可靠人物时段时，在原有低频侦察帧上提取最长边 192 像素的局部运动；补偿曝光与背景平移，检查持续运动及多段歧义。它只分配采样时间，不提供人物裁剪框，不控制录像。
4. 仍无法定位时覆盖完整可读取片段，去掉固定 35%–85% 的时间假设。
5. 提示词按真实时间戳说明采样，不再一律宣称非等间隔；保留裁剪不代表真实移动或转体的约束。
6. 修复末尾窗口量化可能超过小数视频时长的问题，并验证先红后绿。

新版 17 段中：2 段用轨迹、2 段用扩展可见区间、12 段用局部运动时段，1 段（testm）回退完整片段。人物裁剪规则、单组图片、一次模型请求、拍摄触发和结束规则均未变。

## 固定通过条件

- 密集区间边缘各允许 20ms 后，覆盖至少 98% 的独立标注明确腾空区间。
- 实际区间内帧数至少 `max(2, floor(区间秒数 × 8) + 1)`。
- 包括区间两端在内的最大采样空隙不超过 150ms，总帧数不超过 96。
- 丢失结果、源哈希不符、未知标注均不能算通过。

## 验证与代价

- 385 项自动化测试通过；静帧、均匀曝光、平移、抖动、大近景、多段同等运动、安全禁用、资源释放及小数时长末尾均有回归检查。
- 全部 34 路径使用真实原视频解码和真实 JPEG 编码，并在本机截获实际分析请求；没有发往模型。图片尺寸、500KiB 单图和 15MiB 总请求限制全部通过。
- 平均总帧数从 48.56 增至 51.74（约 +6.5%）；若只保守扩窗则为 63.32。局部运动回退减少了无关画面，仍保留单组时序图片。最大样本为 blacktest 的 94 张。
- 扩大不确定区间也有密度代价：9505 的核心帧从 12 减至 9，testm 从 8 减至 4；它们仍通过固定覆盖与间隙条件，不能表述成每段的腾空帧都增加了。
- 最终样本请求约 1.18–2.62MiB，单张最大约 31.9KiB；这不是 token 数或模型费用估计。
- `npm test`、`npm run build`、`npm run validate` 通过。
- 打包页面用原始 9505 完成本地导入、真实取帧、一次模拟分析及 schema 7 保存；430×932 布局无横向溢出或页面错误，回放保持 1×，阶段默认折叠。未调用真实模型，也未在实体 iPhone Safari 上运行。

## 局限

局部运动是启发式候选，不等于人物或腾空。其它运动物体、多人或更复杂机位仍可能定位错误；有歧义时退回完整片段。长视频找不到可靠时段时，64 张密集帧的上限仍可能不足以保留短暂动作。Mac Chrome 的处理耗时不能代表 iPhone Safari。模型动作分类准确度需要另行用真实模型验证，不能由本报告推断。

完整标注、原片哈希、逐帧时间、前后评估、真实 JPEG 和回归脚本留在本机工作区 `work/sampling-coverage-2026-11-17`，不包含在 GitHub Pages 构建中。
